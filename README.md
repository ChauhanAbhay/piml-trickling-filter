# Physics-Informed Machine Learning for Trickling-Filter Systems

**Combining mechanistic modelling with machine learning to investigate biofilm-state inference and dynamic effluent prediction.**

This research project explores how physical understanding of a trickling-filter wastewater-treatment process can be combined with data-driven models. A mechanistic model generates synthetic observations; machine-learning models are then evaluated on their ability to infer selected internal parameters and reproduce the modelled response to changing operating conditions.

> **Research scope:** The experiments described here use synthetic data generated by the project's mechanistic model. The results should not be interpreted as validation on real treatment-plant data or as proof of deployment-ready forecasting.

## Why combine physics and machine learning?

Physics-based models describe system behaviour through governing equations and interpretable parameters. Machine-learning models can learn nonlinear relationships between observable measurements and quantities that are difficult to estimate directly.

This project explores two related questions:

1. **Internal-state inference:** How well can machine-learning models recover a lumped biofilm parameter and related internal quantities from boundary measurements?
2. **Dynamic response prediction:** Can a sequence model learn the effluent response produced by a physics-based simulator during a rainfall-style disturbance?

The broader motivation is to investigate modelling approaches that combine scientific structure with data-driven learning. Similar approaches may be relevant to complex engineering systems, although each application requires its own validation.

## Research workflow

1. **Generate steady-state data** using an Atkinson–How-inspired trickling-filter formulation and Latin hypercube sampling.
2. **Estimate internal-state quantities** from influent and effluent substrate concentrations, hydraulic loading, and temperature.
3. **Simulate transient behaviour** with a depth-discretised transport-and-reaction model.
4. **Train an LSTM** on synthetic trajectories and evaluate its predictions against held-out simulator trajectories.
5. **Inspect metrics and plots** to understand where the models reproduce the simulated behaviour and where errors remain.

## Models and methods

### Steady-state state recovery

The steady-state generator samples influent concentration (`Si`), hydraulic loading (`Q`), temperature (`T`), and biofilm thickness (`h`). Temperature-dependent reaction kinetics and an effectiveness factor are calculated from the model assumptions, and the resulting effluent concentration is computed.

The state-recovery script compares three regressors:

- **Support Vector Regression (SVR)** with an RBF kernel
- **Random Forest Regressor**
- **XGBoost Regressor**

The inputs are the boundary variables `Si`, `Se`, `Q`, and `T`. Targets include the lumped product \(f h k_0(T)\), the effectiveness factor \(f\), biofilm thickness \(h\), and temperature-adjusted reaction rate \(k_0(T)\).

The code uses a fixed random seed and a 70% / 20% / 10% train-validation-test index split. The current script fits models on the training partition and reports metrics on the held-out test partition; the validation partition is created by the split function but is not used for model selection in that script.

### Dynamic PDE and rainfall-style experiment

The dynamic simulator represents substrate transport through the filter depth with advection and first-order biofilm reaction. The rainfall-style event changes influent concentration and hydraulic loading for a limited interval, then returns them to baseline values.

The LSTM script uses four sequential features:

- Influent substrate concentration
- Hydraulic loading
- Temperature
- Effluent substrate concentration

It uses a 45-sample history window at 0.2-hour sampling intervals (9 hours), a 48-unit LSTM layer, and a small fully connected output head. Data are split by complete trajectory into training, validation, and test groups.

The event described as “rainfall” is a prescribed simulation scenario: influent concentration is multiplied by 0.75 and hydraulic loading by 1.25. It is not a measured rainfall dataset.

## Run the experiments

Run commands from the repository root.

### 1. Steady-state dataset and state recovery

```bash
python src/steady_state_generator.py
python src/ml_state_recovery.py
```

Expected generated files:

- `steady_state_dataset.csv`
- `ml_recovery_results.csv`

### 2. Dynamic PDE simulation and LSTM

```bash
python src/pde_generator.py
python src/train_lstm_rain.py
```

The PDE script runs a numerical-versus-analytical consistency check and generates trajectories. The LSTM training script generates its own trajectory dataset and saves predictions, evaluation metrics, and model weights.

Expected outputs from the LSTM script:

- `pde_rain_dataset.csv`
- `lstm_rain_predictions.csv`
- `lstm_rain_metrics.csv`
- `lstm_rain.pt`

### 3. Plotting

The plotting script currently expects outputs from an earlier workflow (`lstm_dynamic.py` and `lstm_predictions.npz`) and also reads the steady-state experiment outputs. The rainfall LSTM script supplied here writes CSV files instead. Therefore, the plotting workflow needs to be updated before all figures can be reproduced end-to-end.

## Evaluation

The scripts calculate regression metrics including:

- **R²** — proportion of target variance explained by predictions
- **RMSE** — root mean squared error
- **MAE** — mean absolute error

Use the generated metrics files to report the actual results after running the code. Do not infer performance from the model architecture or substitute results from a different experiment.

## Important limitations

- **Synthetic data:** the training and test data are generated by the project's own mechanistic simulator, not collected from an operational treatment plant.
- **Simulator agreement is not field validation:** a model that reproduces simulator output has not thereby demonstrated real-world forecasting performance.
- **Identifiability:** the observable boundary response may constrain a lumped parameter combination more strongly than its individual physical factors. Individual state estimates can depend on additional assumptions or known parameters.
- **Assumptions:** the parameter ranges, kinetic relationships, and disturbance design are modelling choices documented in the source files. They should be reviewed before applying the framework to a real system.
- **Reproducibility:** fixed random seeds are used in the main experiments, but results should be regenerated in the intended environment and checked before publication.
